# ② 계획 검토 (gpt)

Claude가 쓴 `작업/원문.md`와 `작업/plan.json`을 **지면 그림과 운영.md에 대조**한다. 덱을 다시 계획하지 않는다. 덱 파일 · build 코드 · 원문.md · plan.json은 고치지 않는다 — 검토 결과만 낸다.

## 1. 볼 것

- `작업/쪽/` 그림 전부(지도서는 4분면 그림으로 글씨를 확인한다) · `입력/운영.md` · `작업/원문.md` · `작업/plan.json`.

## 2. 할 일 (이 순서로)

1. **전사 대조.** 원문.md의 절마다 해당 쪽 그림을 열어 한 줄씩 대조한다. 빠진 문장 · 바뀐 낱말 · 대소문자 · 문장부호 차이를 적는다. 원문.md에 나오는 쪽은 모두 `checked: true`로 남겨야 통과한다.
2. **정답 대조.** 연습의 `answer_src`가 가리키는 지도서 ANSWERS와 계획의 문항을 맞춰 본다.
3. **범위.** 운영.md가 다룬다고 한 지면 활동이 빠졌는지, 다루지 않는다고 한 것이 들어갔는지.
4. **일정 · 과제 조건.** 계획에 적힌 날짜 · 시각 · 분량 · 제출 형식 · 배점이 운영.md와 같은지.
5. **흐름.** 학생이 혼자(자습이면) 넘길 때 막히는 곳: 정답이 든 영상이 연습보다 앞에 오는지, 지면 없이 문항이 나오는지, 한 섹션이 너무 긴지.
6. **제안**(선택, 5개까지). 덱이 더 좋아질 방법. 근거와 함께.

## 3. 작업/review_plan_gpt.json

```json
{
 "reviewer": "gpt",
 "verdict": "agree | partly | disagree",
 "summary": "한국어 2–3문장",
 "transcription": [
  {"page": "지도서 p.21", "checked": true,
   "diffs": [{"원문md": "원문.md의 글", "지면": "그림에 보이는 글", "note": "무엇이 다른가"}]}
 ],
 "items": [
  {"id": "R1", "slide": 12, "type": "정답",
   "issue": "무엇이 문제인가",
   "evidence": {"page": "지도서 p.21", "quote": "지면의 글 그대로"},
   "suggest": "어떻게 고칠까"}
 ]
}
```

- `type`: 원문 · 정답 · 범위 · 일정 · 과제 · 흐름 · 제안.
- **원문 · 정답 · 범위 · 일정 · 과제** 항목에는 `evidence`가 반드시 있어야 한다: 지면이면 `{"page", "quote"}`(지면의 글 그대로), 운영.md면 `{"page": "운영.md", "quote": "운영.md의 글 그대로"}` — 운영.md 인용은 코드가 글자 단위로 대조한다.
- 「내 판단과 다르다」는 이유가 아니다. 규칙 · 지면 · 운영.md에 근거가 없으면 `제안`으로 낸다.
- **지면 근거에는 그림 파일 이름도 적는다**: `evidence.image`에 실제로 읽은 그림(예: `지도서_p21_좌상.jpg`). 받는 쪽이 같은 그림을 원 해상도로 열어 확인한다. (2026-10-13: 지면에 없는 낱말 하나를 「빠졌다」고 한 이의가 있었다 — 코드는 그림 속 글을 대조하지 못한다.)
- 문제가 없으면 `items`는 빈 목록, `verdict`는 agree.

## 4. 마무리

`python "<스킬>/scripts/check.py" review_plan` → 실패한 칸만 고쳐 다시(최대 2번). 통과하면 `status.py gpt`로 다음 차례(③ Claude)를 보고하고 멈춘다.
