# ④ 덱 검토 (gpt)

Claude가 조립한 덱 초안을 **학생이 혼자 넘긴다고 생각하고** 한 장도 빼지 않고 본다. 덱 · build 코드는 고치지 않는다 — 검토 결과만 낸다.

## 1. 볼 것

- `출력/초안/화면/` — 슬라이드 그림(정답 상자를 연 상태). `*_sheet*.png`는 여러 장을 한 장에 모은 것.
- `출력/초안/slides.json` — 슬라이드별 화면 글 · 대본 줄 · 연습 정답 · 노트.
- `작업/원문.md` · `작업/쪽/` · `입력/운영.md` · `작업/plan.json` · `작업/decisions.json`(② 검토에 Claude가 어떻게 답했는지).
- 덱 HTML(`출력/초안/*.html`)을 브라우저로 열어 볼 수 있으면 연습 몇 개를 직접 풀어 본다(선택).

## 2. 찾을 것

1. **원문 · 정답** — 화면의 대본 · 문항 · 정답이 지면 · 원문.md와 다른 곳.
2. **번역 · 해설** — 한국어 번역이 영어와 다른 뜻, 해설이 틀린 곳.
3. **화면** — 글이 잘리거나 겹침, 그림이 안 보임, 한 장에 너무 많음.
4. **조작 · 흐름** — 자습생이 무엇을 눌러야 할지 모르는 곳, 정답이 문제보다 먼저 보이는 곳, 순서가 어색한 곳.
5. **표현** — 학생 수준(A2–B1)에 맞지 않는 영어, 어색한 한국어.
6. **제안**(5개까지) — 자습생에게 덱을 더 쓰기 쉽게 만들 것. 근거(어느 장의 무엇)와 함께.
7. **② 결정 확인** — ②에서 낸 이의에 Claude가 「유지」한 근거가 약하면 다시 짚는다.

## 3. 작업/review_deck_gpt.json

```json
{
 "reviewer": "gpt",
 "verdict": "agree | partly | disagree",
 "summary": "한국어 2–3문장 — 학생으로 넘겨 본 느낌 포함",
 "checked_slides": 54,
 "items": [
  {"id": "D1", "slide": 18, "type": "번역",
   "issue": "무엇이 문제인가",
   "evidence": {"slide": 18, "slide_text": "그 장 화면에 있는 글 그대로"},
   "suggest": "어떻게 고칠까"},
  {"id": "D2", "slide": 23, "type": "정답",
   "issue": "…", "evidence": {"page": "지도서 p.21", "quote": "지면의 글 그대로"}, "suggest": "…"}
 ]
}
```

- `checked_slides` = 초안의 장 수. 모두 보지 않으면 통과하지 못한다.
- `type`: 원문 · 정답 · 번역 · 해설 · 화면 · 조작 · 흐름 · 표현 · 제안.
- **`slide_text`는 코드가 그 장의 화면 글(slides.json)과 대조한다.** 화면에 없는 글을 인용하면 실패한다. 지면 근거는 `page` + `quote`.
- 원문 · 정답 항목에는 evidence가 반드시 있어야 한다.
- **지면 근거에는 그림 파일 이름도 적는다**: `evidence.image`에 실제로 읽은 그림(예: `지도서_p21_좌상.jpg`). 받는 쪽이 같은 그림을 원 해상도로 열어 확인한다. (2026-10-13: 지면에 없는 낱말 하나를 「빠졌다」고 한 이의가 있었다 — 코드는 그림 속 글을 대조하지 못한다.)

## 4. 마무리

`python "<스킬>/scripts/check.py" review_deck` → 실패한 칸만 고쳐 다시(최대 2번). 통과하면 `status.py gpt`로 다음 차례(⑤ Claude)를 보고하고 멈춘다.
